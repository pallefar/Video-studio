# Avatar Render Pipeline → AI Video Studio

Self-hosted AI video studio (Higgsfield-class, single user). v1: avatar render
pipeline on a single RTX 3090. v2 (planned): preset video generation, image
studio, multi-track editor, and a model-provider aggregation layer — see
@docs/roadmap-v2.md. Python GPU layer, React control panel.

## Architecture
- FastAPI + RQ + Postgres + MinIO. GPU worker runs natively, NOT in Docker.
- `packages/schema/models.py` is the single source of truth. TS types are
  generated by `export_ts.py` — never hand-edit `web/src/types/schema.ts`.
- Full hardware and model reference: @docs/pipeline-spec.md
- Milestones and acceptance criteria: @docs/milestones.md
- v2 roadmap, feature map, and licence register: @docs/roadmap-v2.md

## Hard constraints
- GPU worker concurrency is 1. Never spawn parallel GPU workers — 24 GB
  fits one lane. This is asserted in tests/test_queue_topology.py.
- Target is sm_86 (Ampere). NO FP8 — reject Ada/Hopper-targeted builds
  and quantised checkpoints. Use BF16.
- Models load once at worker boot and stay resident. Never load per job.
- The GPU worker MUST be portable to rented GPUs. All artefact I/O goes
  through the S3 interface — never a local path. All service addresses
  come from env — never a localhost literal. The worker is stateless and
  every stage is idempotent on (job_id, stage). Enforced by
  tests/test_portability.py.
- MIT / Apache-2.0 model weights only. Do NOT introduce XTTS v2 (CPML),
  F5-TTS (CC-BY-NC), or Wav2Lip (research-only) — this is a commercial
  product and those licences forbid it. Same rule for video generation:
  Wan 2.x family (Apache 2.0) only. NOT HunyuanVideo (licence void in EU),
  NOT LTX (custom licence + FP8-first), NOT FLUX [dev] variants
  (non-commercial), NOT MusicGen (CC-BY-NC). Full adopt/conditional/rejected
  register: docs/roadmap-v2.md §6. Editor deps: no Remotion and no
  openvideodev/react-video-editor as dependencies (source-available,
  team-gated); OpenCut (MIT) and mediabunny (MPL-2.0) are fine.
- Provider layer (v2): API keys and endpoints come from env only; an API
  provider's output enters the pipeline ONLY as an Asset with
  origin='generated' — no path around the compliance gates. API jobs are
  network jobs on the CPU lane and never take the GPU lock.
- Identity policy (v2): identity training and face-bearing generation
  require an Identity with recorded consent. No face-swap of third
  parties. Structural — enforced in validators/tests like C1-C5.
- B-roll generation NEVER runs inside a render job. Wan 2.2 cannot share
  24GB with Chatterbox + MuseTalk. It is a separate queue with an
  exclusive GPU lock. Asserted in tests/test_gpu_exclusivity.py.
- Stock assets: persist license + source_url at ingest, always.
  has_identifiable_people defaults true; the resolver must never return
  a flagged or unapproved asset.
- Compliance rules C1–C5 (@docs/psd.md §6) are enforced in validators and
  tests, never only in application logic.
- Uploads land private. No code path sets YouTube privacy to public.

## Conventions
- Pydantic v2 everywhere. No dataclasses for API or job models.
- Async in FastAPI routes; workers are sync.
- Structured logging (structlog), never bare print.
- Every stage logs duration to the metrics table — throughput regressions
  are how thermal throttling shows up.

## Gotchas
- SQLModel `table=True` classes skip Pydantic validation on instantiation.
  Compliance validators fire at the API edge (Create schemas) and again in
  api/validators/compliance.py at the publish gate. Never rely on a table
  instance having been validated.

## Commands
- `docker compose up -d` — postgres, redis, minio
- `./scripts/dev_up.sh` — whole studio on a non-CUDA machine (Apple Silicon
  Mac, CI): DEV_ENGINES=1 placeholder voice/lipsync, real everything else.
  See docs/mac-dev.md. Dev engines are opt-in env only — never the default.
- `python scripts/verify_gpu.py` — run before debugging anything GPU-related
- `python worker_gpu/run.py` — native venv, not compose
- `pytest tests/test_compliance.py` — must pass before any publish work
- `python packages/schema/export_ts.py` — after ANY schema change

## Do not
- Add a Node backend runtime. Python API, React SPA, nothing between.
- Add Next.js, SSR, or auth. Single-user localhost tool.
- Containerise the GPU worker.
- Write TS types by hand.
- Add real-time / streaming features. This is a batch renderer.
