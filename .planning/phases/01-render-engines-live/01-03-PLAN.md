<objective>
The tracer: wire ONE path all the way through the render lane with real models — one
sentence of text through real Chatterbox to a WAV in S3, one time window through real
MuseTalk to an MP4 chunk in S3, both models resident in one process.

This is production code, not a prototype. It is the skeleton every later task builds on:
plan 01-04 measures it, plan 01-05 expands it from one window to many. Everything in the
render lane above and below these two methods — chunk window math, GPU locking, the job
state machine, idempotency keys, S3 I/O, emotion mapping — is already built and tested
against fake engines (RESEARCH.md "Key insight"). Resist touching stages.py, chunking.py
or locks.py.

The honest verification split: every piece of logic that is NOT the model call is factored
into `worker_gpu/engines/audio.py` and tested on the Mac with real ffmpeg and a mocked S3.
The model calls themselves cannot be verified without CUDA and are gated in plan 01-04.
That factoring is not test theatre — the artefact-key contract, the window-audio timeline
and the format normalisation are where this phase's integration bugs actually live, and
none of them need a GPU to get wrong.

Purpose: runbook step 2's implementation half (docs/workstation.md §5) — the real engine
loads that unblock `bench.py --smoke`.
Output: two real engines and the shared helper module that defines their contracts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third_party/MuseTalk -> worker module search path | A vendored research repo joins the import namespace of the process that holds the GPU |
| DB (RenderJob / VoiceProfile / BaseLoop) -> engine | Engines now read entity URIs themselves rather than receiving them from the stage |
| ObjectStore -> engine local scratch | Reference audio, loop video and segment WAVs are downloaded to temp files and fed to ffmpeg and the models |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering | third_party/MuseTalk on the import path | medium | mitigate | `MuseTalkEngine.load` appends the clone root to the module search path and never prepends it, so project modules win any name collision; acceptance criterion greps for the prepend form |
| T-01-09 | Tampering | reference audio and loop video fed to model decoders | low | accept | Both arrive only via `VoiceProfile.reference_audio_uri` and `BaseLoop.source_uri`, created through the existing validated API; this plan adds no new upload path (RESEARCH.md Security Domain) |
| T-01-10 | Information Disclosure | engine temp files holding voice reference audio | low | mitigate | Reference audio is cached inside an instance-scoped temporary directory that the OS reclaims with the process; nothing is written to a fixed filesystem location, which the portability test independently enforces |
| T-01-11 | Denial of Service | unbounded window audio reconstruction | low | accept | Windows are bounded to 90 s by `chunk_windows`, and this is a single-user localhost batch tool with no external submission path |
| T-01-12 | Tampering | engine writing to BaseLoop.latents_uri / bbox_uri | medium | mitigate | Explicitly out of scope; acceptance criterion greps lipsync.py for both column names and requires zero hits, so a half-built persisted cache with no invalidation cannot land in this phase |
</threat_model>
