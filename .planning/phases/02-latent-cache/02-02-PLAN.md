<objective>
Make this phase's own acceptance command capable of returning an answer.

Roadmap Phase 2 success criterion 2 is verbatim: `python scripts/bench.py --loop <id>`
compares the two latest lipsync runs and shows the cached run ≥40% faster. That command
cannot work today, and not because the cache is missing. `bench_loop` filters
`Metric.ref.contains(loop_id)` for `stage == "lipsync"` (`scripts/bench.py:75`), but the
only writer of lipsync metrics is `lipsync_stage`'s `@timed_stage("lipsync")` decorator,
whose ref is `str(job_id)` (`packages/pipeline_core/metrics.py:23`,
`worker_gpu/stages.py:107`). `job_id` and `loop_id` are independent UUID4 values; one
containing the other as a substring is astronomically unlikely. Run the benchmark exactly
as documented on a perfectly working cache and it prints "found 0" forever.

There is a second, quieter defect in the same code. Because the decorator wraps the whole
function, the idempotent early return also records a row — a duplicate queue delivery
produces a near-zero-duration lipsync metric, and since `bench_loop` reads the two most
recent rows, that row becomes the "cached run" and the script reports a speedup close to
100%. A false pass is worse than a false fail on an acceptance criterion.

This plan fixes both, entirely on the CPU, before any hardware session. It ships no cache
logic and needs no GPU.

Purpose: runbook step 5 (docs/workstation.md §5), M2.4's measurement mechanism.
Output: a benchmark that returns a true answer, and a regression test that keeps it true.
</objective>

new ref helper, once `job.base_loop_id` is in scope. Two properties of the resulting

sound.

Do not touch `tts_stage`, `generation_stage_local`, `generation_stage_shared` or
`identity_training_stage`. They keep the decorator. Only the lipsync stage has a reader that
