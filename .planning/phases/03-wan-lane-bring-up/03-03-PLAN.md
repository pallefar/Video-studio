<objective>
Build the two things the M10.6 measurement needs and neither of which exists: the
configuration it is supposed to measure, and the instrument that measures it.

The milestone box reads "Benchmark on the 3090: Fun-Camera A14B GGUF + 4-step LoRA latency
and VRAM (decides 14B vs 5B default)". No template in the repository wires a LoRA into any
graph. `scripts/bench.py` covers the render lane only — Chatterbox and MuseTalk — and refuses
to start without a local CUDA device, which is exactly wrong for a lane whose executor may be
a rented card at the far end of an SSH tunnel.

Improvising both at measurement time, on an hourly-billed box, is how a benchmark ends up
reporting a number nobody can reproduce. Both are CPU-buildable now and both are testable now
against a fake ComfyUI, so both get built now.

The measurement discipline is inherited, not invented. Phase 1 established that
`torch.cuda.max_memory_allocated()` under-reports because it excludes the CUDA context, and
rewrote `bench.py` to judge the budget against `nvidia-smi --query-gpu=memory.used`. The wan
lane's two-expert load hits the same trap harder. The one thing that has to be added is
sampling during the run rather than after it: ComfyUI releases the model when a prompt
finishes, so a post-hoc reading measures an idle card.

Purpose: runbook step 8 (docs/workstation.md §5), M10.6.
Output: an audited four-step arm, a wan-lane benchmark mode that works over a tunnel, and a
comparison emitter the 14B-versus-5B decision can be written from.
</objective>

Add a comparison mode on top of Task 2's single-run measurement: accept several models in one
invocation, run each in turn, and emit one record carrying every arm side by side.

Run the arms strictly sequentially. Two generations in flight at once would both be sampled by
the same device instrument and neither peak would mean anything — and on the real card they
would contend for the exclusive wan lane lock in any case. Make the sequencing explicit in the
code and assert it in a test rather than relying on it falling out of a simple loop.

Emit the record to a caller-supplied path as well as to standard output. The measurement will
be taken on a rented instance that is destroyed when the session ends, and a number that exists
only in a terminal is a number that has to be re-measured. Choose a format that a human reads
and a later phase can lift figures from: a table is enough, and it should carry per arm the
model name, the checkpoint filenames read out of the submitted graph, the step count and
