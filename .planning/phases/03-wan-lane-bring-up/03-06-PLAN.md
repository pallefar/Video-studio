<objective>
Bring the executor up on real hardware, and prove the phase's CPU work was verified against the
tree that is actually installed.

Everything before this plan asserted things about node classes by reading upstream source at
planning time. The packs are cloned at whatever HEAD exists at install time. Research Pitfall 3
names the gap, and there is exactly one moment where closing it is cheap: the first time a real
ComfyUI is running, before any generation has been attempted. One query of the running server's
object listing returns every node class's real inputs and outputs, and comparing that against the
signature registry settles in minutes whether the last four plans were built on sand.

The other reason this plan is separate from the generation work is cost. The model roster is tens
of gigabytes, the licence register in roadmap-v2 §6 is binding, and the HuggingFace repositories
carry assumed provenance because no automated legitimacy check exists for model weights the way it
does for package registries. That review is a blocking human gate and it belongs before the
download, not after it — the same shape Phase 1 used for its engine dependency's commit pin.

This is runbook step 6 and phase success criterion 1.

Purpose: an executor that is online, complete, correctly bound, and demonstrably the same one the
phase's structural work assumed.
Output: recorded commits, a clean node diff, and a verified signature comparison.
</objective>
