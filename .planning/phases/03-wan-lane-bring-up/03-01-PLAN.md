<objective>
Build the machinery that makes every remaining CPU task in this phase provable, and prove it
end to end on the one model this phase is missing entirely.

Ten of the thirteen shipped workflow templates are structurally broken. The existing
structural audit, `tests/test_comfy.py::test_every_model_has_a_structurally_valid_template`,
passes all thirteen — it only walks the `inputs` path map and checks each path resolves
inside the graph JSON. It never asks whether a referenced node OUTPUT index exists, never
asks whether a node carries the inputs its class declares `required`, and never asks whether
a node the template patches a value into is connected to anything. Three blind spots, and
every one of the ten defects lives in one of them.

The third was found by running a reachability sweep over the shipped graphs during planning
and is not in the research document, so treat it as a first-class finding rather than a
footnote. Five templates contain a node that the designated output node cannot reach by
following edges backwards: `wan2.2-i2v`'s image loader, `wan2.2-vace-fun`'s and
`wan2.1-vace-1.3b`'s video loaders, `wan2.2-fun-camera`'s camera-embedding node, and
`sdxl`'s LoRA loader. In every one of those five the orphaned node is the target of an entry
in the template's own `inputs` map, so the studio uploads the asset, patches its filename
into the graph, and the graph ignores it. A Fun-Camera generation applies no camera motion.
An image-to-video generation generates from the prompt alone. An identity-LoRA image
generation uses no identity. None of them errors; all of them return a plausible clip. This
is the worst defect class in the phase precisely because it is the only one that never
announces itself.

This plan closes both blind spots with a signature-driven audit, and drives that audit
through every layer of the phase by using it to build the one thing the roadmap's M10.6
decision cannot happen without: a real `wan2.2-ti2v-5b` path. Roadmap-v2 §9 names the 5B as
the fallback the Fun-Camera benchmark decides against, and no ModelSpec, template, or
download for it exists anywhere in this repository. You cannot benchmark 14B-vs-5B with one
arm.

Purpose: runbook steps 6-8 are worthless if they execute graphs that were never going to
run. Every defect this audit catches is a defect that would otherwise be discovered on an
hourly-billed rented card.
Output: an audit with recorded provenance and proven teeth, a working 5B path, and an
`inject()` that can keep two nodes' shapes in sync.
</objective>

Implement `audit_graph` in the same module. It takes a ComfyUI API-format graph dict and
returns a list of human-readable defect strings, empty when the graph is sound. Four checks,
each phrased so its message names the node id, the field, and what was expected:

  1. Edge target exists: any input value that is a two-element list whose first element is a
     string must name a node id present in the graph. A dangling reference is a defect.
  2. Output index in bounds: when that source node's class has a recorded output tuple, the
     second element must be a non-negative integer strictly less than the tuple's length.
     This is the check that catches a clip edge taken from output index 1, or a vae edge from
     index 2, of a loader that has exactly one output.
  3. Required inputs present: when a node's class has a recorded required-key tuple, every
     one of those keys must be a key of that node's own `inputs` dict. This is the check
     that catches the missing video-combine fields, and it is the check that would catch a
     wrong loader key name if the source reading above found one.
  4. Signature coverage: any class type that appears as the SOURCE of an edge but has no
     entry at all in the signature mapping is itself a defect, because the audit is blind to
     it. An entry whose outputs are recorded as unverified is NOT a coverage defect — it is a
     declared blind spot, which Task 2 makes visible as its own list.
  5. Reachability: starting from the graph's designated output node and walking edges
     backwards through every input that is a node reference, collect the transitive closure.
     Any node outside it is a defect, because nothing it computes can influence the result.
     Word the message to say what it actually means for the caller — the node is unreachable
     from the output, so any value patched into it is discarded. This check needs the output
     node id, which lives on the template rather than in the graph, so give `audit_graph` an
     optional output-node parameter and skip the check when it is not supplied; the
     template-level caller always supplies it. Five shipped templates fail this check today
     and in all five the orphan is the target of an `inputs` mapping, so also report, as part
     of the same defect string, which parameter is thereby inert — that is the sentence a
     reader needs, not the node id.

Keep `audit_graph` a pure function over its arguments with the signature mapping as a
