  <name>Task 1: The SDXL template's identity-LoRA node is connected to nothing — remove the claim, or build the mechanism</name>
  <decision>Whether `sdxl.json` keeps a LoRA path at all in this phase, and if so how a graph that must work both with and without an identity LoRA is expressed, given ComfyUI graphs have no conditionals.</decision>
  <context>
`sdxl.json` contains a LoRA-loading node at id 50. It takes its model and clip inputs from the
checkpoint loader correctly. Its outputs are read by nothing: the sampler takes its model
straight from the checkpoint loader, and both text-encode nodes take their clip straight from
the checkpoint loader. The node sits in the graph, computes, and is discarded.

The template's `inputs` map points the `lora_name` parameter at that node. `build_values`
populates `lora_name` from an identity's trained LoRA uri whenever a generation carries one.
So the full path exists — the trainer writes weights, the API attaches the identity, the
worker derives the filename, the injector patches it in — and the last step drops it. Every
identity-bearing image generation this project has produced used no identity.

Why it is not a one-line fix: pointing the sampler and the text encoders at the LoRA node
makes the LoRA mandatory. A generation with no identity supplies no `lora_name`, the node
keeps its empty default, and ComfyUI fails to load a weight file named by an empty string. The
template would go from silently ignoring identities to loudly refusing ordinary generations.
ComfyUI has no conditional nodes, so "apply the LoRA only when there is one" has to be
expressed somewhere else — most naturally in the studio's template selection, which today is a
single `load_template(generation.model)` call.

Scope note: `sdxl` is an image-studio model. This phase's requirement is the generative B-roll
lane. It is on the table because the plan 03-01 audit flags it and the ratchet cannot empty
around it. Roadmap Phase 5's goal already includes "a trained identity is usable across image
studio, storyboards, and avatars", which is the phase that would naturally own the mechanism.

None of the options below removes a capability the product has. The capability is absent
today; the disagreement is about how visibly.
  </context>
